# 国际化架构与开发约定

## 选型

采用 Paraglide JS 3（`@inlang/paraglide-js`）。语言文件编译为带类型声明的消息函数，适合 TypeScript、Svelte 5 与 SSR。编译器和格式插件都是构建依赖，站点运行时不向翻译服务发送请求。

不使用模块级可变语言 store。服务端通过 Paraglide 中间件的 AsyncLocalStorage 绑定请求语言；Cloudflare Pages 配置 `nodejs_compat` 支持该能力，不关闭请求隔离。

参考：[SvelteKit 集成](https://paraglidejs.com/sveltekit)、[编译流程](https://paraglidejs.com/build-workflow)、[语言策略](https://paraglidejs.com/strategy)。

## 当前语言策略

- 基础语言：`zh-CN`；另一种已提供语言：`en`。
- 解析顺序：`tsnav_locale` Cookie → 基础语言。未选择、无效 Cookie 都回退中文；不根据浏览器语言自动改变默认值。
- 页头 `LanguageSwitcher.svelte` 用 `setLocale()` 保存选择并整页重载。切换会清除页面局部搜索和筛选状态；不使用 `reload: false` 绕过 SSR 同步。
- 语言不写入 URL，当前所有语言共用 `/`。这适用于当前导航站的语言偏好基础能力；以后需要多语言 SEO 时再统一设计本地化 URL 和 reroute，不在组件中拼接路径。
- `app.html` 的 `%lang%` / `%dir%` 在服务端替换，初始 HTML 即具有正确语言、方向和翻译后的元数据。
- 按 Cookie 区分的 HTML 添加 `Vary: Cookie` 和 `Cache-Control: private, no-store`，不让共享缓存复用其他语言页面。后续若新增本地化 API 或数据响应，需同时设计其缓存策略。

## 文件职责

| 文件 | 用途 |
| --- | --- |
| `project.inlang/settings.json` | 基础语言、支持语言、消息文件路径与本地格式插件 |
| `project.inlang/paraglide.config.js` | Vite 与 CLI 共用编译设置和语言策略 |
| `messages/zh-CN.json` / `messages/en.json` | 唯一可编辑的翻译源 |
| `src/lib/paraglide/` | 自动生成的消息、运行时和服务端模块，不提交、不手改 |
| `src/hooks.server.ts` | 请求上下文、HTML 语言与方向、缓存边界 |
| `src/lib/components/LanguageSwitcher.svelte` | 最小语言选择入口 |
| `scripts/check-messages.mjs` | 消息键、空字符串与插值参数一致性检查 |

格式插件从项目 `node_modules` 加载，版本由 pnpm 锁定，不依赖构建时下载 CDN 脚本。`src/hooks.client.ts` 继续只处理 Material 注册，不重复创建语言状态。

## 添加文案

在两个 JSON 文件同时增加相同的扁平键，使用语义前缀，如 `search_label`、`site_open_label`。当前源文件均为非空纯文本字符串，插值写作 `{name}`。

```svelte
<script lang="ts">
  // 展示当前语言下的站点无障碍提示。
  import { m } from '#lib/paraglide/messages.js';
</script>

<span>{m.site_open_label({ name: 'GitHub' })}</span>
```

消息键和参数由生成类型检查。动态分类使用有限、显式的函数映射 `categoryLabels`，而非构造字符串后调用 `m[key]()`。

- 所有界面文案，包括 aria-label、placeholder、title、meta description、空状态、计数，均由消息函数提供。
- 品牌名（TSNav、GitHub 等）、站点缩写和语言自称（简体中文、English）可作为稳定标识保留；语言自称带对应 `lang` 属性。
- `Category` 使用 `development/design/reading` 稳定 ID，不以翻译后的文字作为状态或数据键。
- 示例站点 `description` 保存消息函数引用，渲染或搜索时调用。禁止在模块顶层调用消息函数并保存结果，否则会脱离请求上下文。
- 不向翻译写入 HTML 后通过 `{@html}` 渲染；需要富文本、复数或选择变体时，先按框架格式扩展当前检查脚本与使用约定。当前英文计数使用 `Sites: {count}`，不需要拼接单复数词尾。

## 增加语言

1. 在 settings.json 的 locales 中增加 BCP 47 语言标记。
2. 增加 `messages/<locale>.json`，保持所有消息键和插值参数一致。
3. 在语言入口增加该语言的自称，并设置对应 lang。
4. 执行下列检查，并增加新语言的 SSR 与切换验证。文本方向由运行时的 getTextDirection 处理；新增 RTL 语言时还需检查布局方向适配。

## 命令与验证

```sh
pnpm i18n:check
pnpm i18n:compile
pnpm check
pnpm build
pnpm test:e2e
```

`pnpm check` 先检查语言资源，再编译消息、生成 SvelteKit 类型，最后运行 svelte-check。因此全新检出时无需先启动 dev server。`pnpm build` 先校验资源，再由 Vite 插件生成消息并构建。

翻译源修改需要重新构建发布。生成目录不会提交；不要把生成代码当成开发 API 手工维护。中文 JSDoc 规范适用于项目手写代码，不要求修改第三方编译器输出。

浏览器回归覆盖两种语言切换、刷新持久化、标题与 Material 输入标签、SSR 并发隔离、未知语言回退，以及原有的主题和搜索行为。
